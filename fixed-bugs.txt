Fixed bugs
==========

2026-11-15  Path box kept a mistyped path after a failed navigation
  Symptom: typing a non-existent folder and pressing Enter left the bad text in the
           path box although the list still showed the old folder.
  Fix:     NavigateRemote/NavigateLocal restore the current folder (UpdatePathBox) on failure.

2026-11-15  External subtitles from the remote folder were loaded but not shown
  Symptom: "Movie.srt" next to "Movie.mkv" on the server was added but stayed disabled.
  Cause:   sub-add was called with the "auto" flag, which means "do not select".
  Fix:     the first matching subtitle is added with "select", others with "auto".

2026-11-15  Wheel / arrow seeks jumped by much more than 5 s
  Symptom: one wheel notch moved from 0:03 to 0:10 on files with sparse keyframes.
  Cause:   mpv relative seeks snap to keyframes by default.
  Fix:     hr-seek=yes (precise seeks).

2026-11-15  Size column clipped values like "156.8 KB"
  Fix:     widened the Size column.

2026-11-15  Buffering / stalls on far-away (high-latency) connections
  Symptom: on distant servers playback stalled, and after a seek the picture froze for
           several seconds (300 ms RTT test: ~6 s freeze after a +30 s seek).
  Cause:   remote data was fetched one block per round trip, only when mpv asked for it
           (strict request/response, chunks restarting at 256 KiB after every seek), so
           throughput was capped by latency and nothing was buffered around the position.
  Fix:     each remote stream now has a background prefetch thread and a block cache that
           keeps 5 s before and 5 s after the read position (size/duration estimate, 2-96 MiB),
           fetched with pipelined requests (8-32 x 256 KiB in flight, SshConn::readPipelined),
           current block first, then a little ahead, then the 5 s behind, then the rest ahead.
           mpv: cache-pause-initial (start once 5 s are buffered), cache-pause-wait=5 (resume
           after a stall with 5 s buffered), demuxer-seekable-cache=yes (instant seeks back).
           Result in the same test: playback resumed 0.24 s after the seek, no stalls.
           Pipelining alone: 5.5 -> 11.5 MiB/s at 150 ms RTT.

2026-11-16  Remote files showed no size in the file list
  Symptom: the Size column was empty for every file on the SSH server (local files had sizes).
  Cause:   the remote L (list) command only sent names (ls -1ApL), so the app never got sizes.
  Fix:     L now returns "<size>:<type>:<name>" per entry from a single command per folder,
           picking what the server has (detected once per connection): GNU find -printf,
           else stat -c (GNU/busybox), else stat -f (BSD/macOS), else ls (no sizes, as before).
           Parser splits on the first two ':' so names containing ':' still work.
           Tested with GNU tools and busybox applets (names with spaces, ':', leading '-',
           dotfiles, unicode, symlinked folder, empty folder).

2026-11-16  File sizes showed a truncated unit ("115.2 M", "156.8 K")
  Symptom: sizes of 1 KB and up lost the second letter of the unit (local and remote lists).
  Cause:   swprintf(L"%.1f %s", ..., L"MB") - with this MinGW C runtime %s expects a narrow
           string, so only the first wide character was printed. The 2026-11-15 entry
           "Size column clipped values" misdiagnosed this as column width.
  Fix:     use %ls (wide string) in FormatSize.
